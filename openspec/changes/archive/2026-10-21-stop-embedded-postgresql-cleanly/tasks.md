## 1. Reproduce the unclean stop

- [x] 1.1 Add a `clean-shutdown` case to `e2e/docker-storage/run.sh` and to its `all` list. Add a helper that reads `Database cluster state` with `pg_controldata` from a helper container on a stopped volume. The first part of the case starts the candidate on a named volume and waits for health. It stops the container with `docker stop` and the default timeout, then asserts three things: the stop took less than 10 seconds, the exit status is `0` and the cluster state is `shut down`. Verify that `docker build --tag databasus-storage-test:local .` succeeds and that `CASE=clean-shutdown DATABASUS_IMAGE=databasus-storage-test:local bash e2e/docker-storage/run.sh` fails, because the current image leaves the state `in production`.
- [x] 1.2 Add a `startup-stop` case and add it to the `all` list. Each of its two parts starts the candidate on a fresh volume and runs a `docker exec` loop inside the container. The loop waits for the target process and sends it `SIGSTOP`. In the first part the target is a `postgres --single` process. In the second part it is the postmaster of the regular server, a `postgres` process without `--single` whose PID matches `postmaster.pid`. With the target frozen, the case starts `docker stop` in the background. In the first part only, it asserts that `Stop requested during startup` appears in the log within 2 seconds while the target is still stopped. In the second part, a foreground `pg_isready` or `psql` call can wait on the frozen postmaster, so the case sends `SIGCONT` without that assertion. In both parts, the case then sends `SIGCONT` to the target where not yet sent and asserts that the container exits with status `143`, which rules out a kill by the stop timeout, and that the log has no `Starting Databasus application...` line. In the second part it also asserts that the cluster state is `shut down`. Verify that `CASE=startup-stop DATABASUS_IMAGE=databasus-storage-test:local bash e2e/docker-storage/run.sh` fails against the current image.

## 2. Supervise the services

- [x] 2.1 In `docker/start.sh`, split `main` into a root phase and a runtime phase under `databasus`, following design decision 1. The root phase ends with `exec gosu databasus /app/start.sh` and a phase argument, and the PostgreSQL steps drop their `gosu databasus` prefix. Install a `TERM` and `INT` trap at the start of each phase, following design decision 4. Before the application starts, the handler logs `Stop requested during startup` and stops the PostgreSQL process running at that moment. The regular server receives `SIGINT` for a fast shutdown, a single-user step `SIGTERM`. The handler waits in a loop while `kill -0` succeeds and then exits with `143` or `130`. Run the single-user steps in the background, followed by `wait` on their process ID. Verify that `docker build --tag databasus-storage-test:local .` succeeds and that `CASE=startup-stop DATABASUS_IMAGE=databasus-storage-test:local bash e2e/docker-storage/run.sh` passes.
- [x] 2.2 Replace `exec gosu databasus ./main` with a supervision function that follows design decisions 1, 2, 3 and 5. It starts the application in the background, waits on both process IDs with `wait -n` and forwards a stop signal to the application. It repeats `wait -n -p` until Bash names the process that exited, collects every status with `|| status=$?` and logs `Databasus application exited with status <n>`. Afterwards it sends the postmaster `SIGINT` for a fast shutdown, waits for it to exit and exits with the application's status. When PostgreSQL ends first, it stops the application and exits with `1`. Verify that `docker build --tag databasus-storage-test:local .` succeeds and that `CASE=clean-shutdown DATABASUS_IMAGE=databasus-storage-test:local bash e2e/docker-storage/run.sh` passes.

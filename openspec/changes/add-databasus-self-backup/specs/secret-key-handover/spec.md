# Spec Delta

## Purpose

Один раз показывает root admin ключ шифрования инстанса и требует подтвердить, что ключ сохранён. Без ключа бэкапы Databasus и бэкапы баз невозможно восстановить на другом сервере.

## ADDED Requirements

### Requirement: Root admin видит ключ, пока не подтвердит, что сохранил его

Когда root admin открывает интерфейс, в том числе с сессией, открытой ещё до обновления, он SHALL видеть экран с ключом шифрования инстанса, пока не подтвердит, что сохранил ключ. Экран SHALL объяснять, что без ключа бэкапы нельзя восстановить на другом сервере и что после подтверждения ключ можно будет найти только на сервере, в файле ключа. Экран SHALL показывать абсолютный путь к файлу ключа, которым пользуется сервер (`SecretKeyPath`), в Docker-образе это `/databasus-data/secret.key`. Экран SHALL позволять скопировать ключ и скачать его файлом. И скопированное значение, и содержимое файла SHALL быть значением ключа с сервера без пробелов и переводов строки по краям, то есть тем значением, которое принимает восстановление. Если файл ключа на сервере кончается переводом строки, восстановление само подбирает этот вариант, поэтому выданного значения хватает.

Это SHALL одинаково работать после регистрации, после первого входа через внешнего провайдера, для root admin, созданного командой на сервере, и на инстансе, обновлённом до версии с этой возможностью. Если root admin закрыл экран без подтверждения, экран SHALL появиться при следующем входе.

#### Scenario: Первая регистрация

- **WHEN** первый человек регистрируется на пустом инстансе
- **THEN** сразу после регистрации в Docker-образе он видит ключ и путь `/databasus-data/secret.key`

#### Scenario: Первый вход через Google или GitHub

- **WHEN** первый человек входит на пустой инстанс через Google или GitHub
- **THEN** после возврата от провайдера он видит тот же экран с ключом

#### Scenario: Обновлённый инстанс

- **WHEN** root admin инстанса, обновлённого до этой версии, входит в первый раз после обновления
- **THEN** он видит экран с ключом

#### Scenario: Сессия открыта до обновления

- **WHEN** root admin вошёл до обновления, не выходил из аккаунта и открывает интерфейс после обновления
- **THEN** он видит экран с ключом, не входя заново

#### Scenario: Root admin создан командой на сервере

- **WHEN** оператор создал первый аккаунт командой на сервере, и этот root admin входит в первый раз
- **THEN** он видит экран с ключом

#### Scenario: Копирование и скачивание ключа

- **WHEN** root admin копирует ключ и скачивает его файлом
- **THEN** в буфере обмена и в файле ровно значение ключа без пробелов и переводов строки по краям, даже если в файле ключа на сервере в конце стоит перевод строки

#### Scenario: Экран закрыт без подтверждения

- **WHEN** root admin закрыл вкладку, не подтвердив сохранение ключа, и вошёл снова
- **THEN** экран с ключом появляется снова

### Requirement: После подтверждения ключ больше не выдаётся через интерфейс и API

После того как root admin подтвердил сохранение ключа, система SHALL NOT отдавать ключ ни одному пользователю, включая root admin, ни через интерфейс, ни через API. Подтверждение SHALL записываться в журнал аудита.

#### Scenario: Подтверждение сохранения

- **WHEN** root admin подтверждает, что сохранил ключ, и потом входит снова
- **THEN** журнал аудита содержит запись о подтверждении без самого ключа
- **AND** экран с ключом больше не появляется

#### Scenario: Запрос ключа после подтверждения

- **WHEN** root admin запрашивает ключ через API после подтверждения
- **THEN** система отказывает и не раскрывает ключ

### Requirement: Ключ видит только root admin

Система SHALL отдавать ключ только root admin. Другие администраторы и все остальные пользователи SHALL NOT получать ключ ни при каких условиях. Каждый показ ключа SHALL записываться в журнал аудита.

#### Scenario: Другой администратор запрашивает ключ

- **WHEN** администратор, который не является root admin, запрашивает ключ до того, как root admin подтвердил его сохранение
- **THEN** система отказывает и не раскрывает ключ

#### Scenario: Участник и запрос без входа

- **WHEN** пользователь с ролью MEMBER или запрос без входа запрашивает ключ до того, как root admin подтвердил его сохранение
- **THEN** система отказывает и не раскрывает ключ

#### Scenario: Журнал показов

- **WHEN** root admin открывает экран с ключом
- **THEN** журнал аудита содержит запись о показе ключа без самого ключа

### Requirement: Восстановленный инстанс не показывает ключ повторно

Состояние подтверждения SHALL переноситься в бэкап Databasus и восстанавливаться вместе с ним. Если на старом инстансе root admin подтвердил сохранение ключа до снятия бэкапа, восстановленный инстанс SHALL NOT показывать ключ снова: состояние подтверждения пришло из бэкапа, а ключ — тот самый, которым бэкап сделан. Если бэкап снят до подтверждения, восстановленный инстанс SHALL показать экран с ключом root admin так же, как на исходном инстансе до подтверждения.

#### Scenario: Вход после восстановления

- **WHEN** root admin входит в инстанс, восстановленный из бэкапа, сделанного после подтверждения
- **THEN** экран с ключом не появляется, а запрос ключа через API отклоняется

#### Scenario: Бэкап снят до подтверждения

- **WHEN** root admin входит в инстанс, восстановленный из бэкапа, снятого до подтверждения
- **THEN** он видит экран с ключом

## Plan review

The candidate is a plan the user has not seen yet.

- Check that the plan solves what the latest user request actually asks, at the right layer and scope. The plan drops no requirement from the request.
- Check that the names, file placement and behavior the plan proposes follow `AGENTS.md` and the module docs.
- Reject a plan that keeps backward compatibility the user did not ask for, treats a symptom and leaves the cause, or misses a clearly more complete approach.
- Whether the task is needed and whether a much simpler option exists is checked by a separate reviewer.
- Reject implementation work done in a mode that only allowed planning.
- Apply the humanizer rules to the plan's prose.
- Architecture is checked by a separate reviewer. Mention architecture only when a violation breaks the request itself.
